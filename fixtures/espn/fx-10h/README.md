# fx-10h — the derived Skills league (plumbing, never evidence)

The reference-format fixture league the Skills, the end-to-end suite and the smoke run against
(research 06 §D.0; plan 09 §4; plan 10 §3.1a *Fixtures* class 2). **Derived, not recorded**: every
file is `derived: true` in its manifest, and the golden test never reads this tree
(`tests/golden/recorded.ts` refuses any path outside `fixtures/espn/recorded/`). `match: true` from
`espn_get_box_score` here is plumbing, never engine evidence — the engine's evidence is the recorded
golden.

Generated by `npx tsx scripts/gen-fixtures.ts` (check: `--check`); never edit by hand. The script
refuses to run unless the recorded golden is green.

## The league

| | |
|---|---|
| format | 10 teams, H2H points, the reference scoring (05 §0): half-PPR (53 at 0.5), 5-point passing TD (4 at 5), 6-point rushing/receiving TD, −2 interceptions and fumbles lost, ESPN-default yardage, the standard K and D/ST families |
| lineup | QB, 2 RB, 2 WR, TE, FLEX, D/ST, K, **5 BE, 2 IR** |
| waivers | rolling (move to last), no budget, 24 h, every day but Tuesday; the Wednesday 03:30 ET run clears the week |
| schedule | 14 regular-season matchup periods, 6 playoff teams (weeks 15–17), seeded `TOTAL_POINTS_SCORED` (record first, points the tiebreak — D1); trade deadline 2026-12-02 |
| teams | `Team 01` … `Team 10`, members `Member 01` … `Member 11` in the fake GUID range, league id `0`; the user is **Team 02** (waiver rank 2) |
| clock | **Tuesday of week 5, 21:00 ET** (`2026-10-07T01:00:00Z`): weeks 1–4 final, week 5 pre-kickoff, before the waiver run |
| public | yes on every variant but the three private ones (`private-league`, `private-league-none`, `private-expiring`) — fixture mode never holds a cookie, so every view is answered keylessly, the league's transaction feed included (ESPN serves it to anyone on a public league); the user's own pending claims are never read keyless (changelog §R10, R10-10); fixture mode answers them by the variant's scripted credential state (changelog §R10, R10-21): `not_configured` (the base and every variant that scripts nothing) gives `pending: null` with the no-session warning, `rejected` (auth-rejected) gives `pending: null` with the rejected-session warning, and `stored` or `validated` (public-league, or after an accepting espn_check_auth) serves the recorded `mPendingTransactions` (`pending: []`). Three variants record a private league (`isPublic: false`; changelog §R10, R10-27, R10-28). On them the scripted state governs every league read, as a session would: `private-league` (`rejected`; its espn_check_auth accepts), `private-league-none` (`not_configured`: `ESPN_REQUIRES_COOKIES`), `private-expiring` (`stored`, `rejects: first_uncached_read`: espn_get_status says `stored` until the first read the store does not serve, which answers `ESPN_AUTH_REJECTED` as ESPN's 401 would, and the label is `rejected` from then on; its espn_check_auth accepts, and a validated session is never rejected). Each refusal has zero requests and spends none of the call's budget, and a fresh cache entry is served first |

## How it is derived

- **Rosters, lineups, schedule, teams** come from `recorded/league-b` (the 10-team half-PPR league),
  fitted to 5 BE + 2 IR (a benched `OUT`/`INJURY_RESERVE` player moves to IR, otherwise the
  least-owned never-started bench player is released to the pool).
- **Raw stats** (`stats{}`) are the recorded ones of all three leagues. The recordings end at week 3
  for rostered players, so week 4's actual and projected lines and week 5's projection **copy the
  newest earlier recorded week** (counted in `manifest.json` `derivations`); a player whose pro team
  is on bye gets no line. Weeks 4 and 5 copy week 3's lineup, with a starter on bye swapped for the
  best eligible bench player.
- **Every scoring field** — `appliedStats`, `appliedTotal`, team totals, `winner`, records, points
  for/against, seeds — is re-scored by the engine under the reference settings and re-checked with
  `verify` (R3 nit (b): the scoreboard, the standings and the seeding simulator agree with the box
  scores). Season-to-date splits are the sum of the weekly lines; a D/ST season projection the
  engine cannot score (summed points-allowed tiers) carries the mean weekly projection × weeks.
- **Pool**: every player with a recorded line (rostered `ONTEAM`, the rest `WAIVERS` before the run),
  in `league/pool.json`; the derived-league fetch (`src/providers/espn/fixture-league.ts`) filters,
  sorts and pages it for each `kona_player_info` request.
- **Transactions**: the week-2 and week-3 roster moves as `WAIVER`/`FREEAGENT` rows plus one
  `WAIVER_ERROR` for Team 02 (synthetic ids in the fake range).
- **Last season (2025)**: final standings for the seeding evidence; seeds follow the record.
- **Pro schedule**: the recorded 2026 view with every week-4 game marked `statsOfficial`.
- **Outlooks**: the scrub leaves every ESPN outlook a placeholder (`[outlook N chars]`), except one
  synthetic sentence of ours: Team 02's first starting RB by player id (James Cook III) carries a
  neutral season outlook that states no claim (`SYNTHETIC_OUTLOOKS.neutral` in
  `scripts/fx10h/variants.ts`), so a check of ESPN's outlook on the base fixture has text to quote.

## Variants

One directory each; its `manifest.json` lists every view, pointing at the base body plus a JSON
patch (RFC 6902 add / remove / replace) where the variant differs — so a variant's files show
exactly what it changes. `EFF_FIXTURE_DIR=<abs>/fixtures/espn/fx-10h/<variant>`.

`writes-on`, `auth-rejected` and `public-league` change only server state fixture mode cannot hold
(the write gates, a credential): their bodies are the base's and their `harness` block names the
state (`auth-rejected`: a stored session ESPN rejected, on the base's public league, where the transaction feed still answers keylessly and pending claims answer `pending: null` with the rejected-session warning, as espn_get_status reports — changelog §R10, R10-10, R10-21). Fixture mode reports a scripted `credential_state` (`rejected`, `stored`) as a label, and its
one `espn_check_auth` answers the scripted `probe` result — never a value, no request
(`src/services/fixture-credential.ts`; changelog §R9, R9-3). `private-league` (changelog §R10,
R10-27) is the base with `isPublic: false` in every body that carries it (`mSettings`, `mNav`,
`mBoxscore`) and a scripted `rejected` session whose one `espn_check_auth` accepts (`settings`
probe: the user re-ran setup), so the label moves to `validated` in memory. Fixture mode reads the
recorded `isPublic` before any request (`derivedLeaguePublicity`): on this variant alone the label
also governs the `auto` and `feed` reads — under `rejected` the first league read (`espn_get_league`
included) is the `ESPN_AUTH_REJECTED` short-circuit with no request, so `league.is_public` stays null
until a body is read (orient's private-league hand-off, changelog §R10, R10-7). A cache entry still
fresh is served before the label is asked, as the real pipeline serves it: a seed that runs
`espn_check_auth` (now `validated`) and then `espn_get_league` leaves the settings fresh in the
state, and a run started again on it reads them while the transaction feed, the standings, the
rosters and the pool are refused — `espn_analyze_league_activity`'s session-refusal partial lines
(changelog §R10, R10-11, R10-18). A seed must not read the feed (`mTransactions2` is cached: a fresh
copy is served too). The plugin eval grades R10-7's private-league hand-off on this variant as
committed (`league.is_public` null: WK-8, SS-13, ON-6, SC-9; SC-10 the accepting probe after the
user re-ran setup), and the `is_public: false` row after the build's `private-settings-fresh` seed
(`espn_check_auth`, then `espn_get_league` only: WK-9), where orient hands over at Step 0.
`private-league-none` is the same private league with no session stored (`not_configured`): every
league read answers `ESPN_REQUIRES_COOKIES` with zero requests, `league.is_public` stays null, and its
`espn_check_auth` answers `accepted: null`, reason `not_configured` — session-check's private-league
