# 06 — Automation inventory (zero-token jobs)

**Author:** `architecture-planner-core` · **Date:** 2026-09-30 · **Brief:** `docs/scratch/briefs/architecture-planner-core.md`
**Inputs:** plans 01 (refresh model D10, data classes §5.2, freshness §5.4, drift probe §7, request budget §5.6), 02 (credential lifecycle §2, journal §4.4, supply chain §7), 03 (doctor §5, launchd, uninstall), 04 (CI jobs, what can be built now §4.6), 05 (fixtures, smoke, evals); `docs/research/04-data-sources.md` §D (freshness map) and §B (cadences); `03-espn-api.md` §B.1 (`waiverProcessDays`/`waiverProcessHour`), §D.3 (budget), §F.2 (the probe); the sibling's inventory `yahoo-fantasy-football-mcp@f3a0a48 docs/plan/06` (**[V-sib 06 §x]** — the launchd design, the dataset-job pattern and the failure-signal model transfer; the credentialed jobs are redesigned for cookies and the drift probe is new).

Legend as in plan 01.

**Principle:** every job here runs **without a model** — a CLI subcommand or a CI workflow whose output is a table, a diff, a notification, or a red build. Anything that needs ESPN cookies runs **only on Chad's Mac**; CI never holds them (plan 04 §4). Jobs are **idempotent and season-aware** (they consult `ds_pro_schedule` and exit 0 in seconds when there is nothing to do), and every ESPN-touching job counts against the same cross-process limiter as the server (plan 01 §6) — the whole inventory is sized to **≤ 40 ESPN requests per day** from jobs, so that with normal chat use the account stays at "tens of requests per day" [V-03 §D.4].

## 2. launchd design

- Labels `io.github.<owner>.eff.<job>`; one plist per job in `~/Library/LaunchAgents/`; generated by `eff install-launchd [--jobs …]` from templates in `src/cli/launchd/` with `ProgramArguments` = `[<process.execPath>, <abs dist/cli.js>, "<subcommand>", "<arg>"]` — the observed `fnm` layout on this machine is `<home>/.fnm/node-versions/vX.Y.Z/installation/bin/node`, which is exactly why the path is resolved and never typed — `EnvironmentVariables` = the non-secret config only (`ESPN_LEAGUE_ID`, `ESPN_SEASON`, `EFF_CACHE_DIR`, `EFF_CREDENTIAL_STORE`; **never a cookie** — the jobs read the same keychain/file store as the server), `StandardOutPath`/`StandardErrorPath` under `~/Library/Logs/espn-fantasy-football-mcp/<job>.log`, `ProcessType Background`, `LowPriorityIO true`, `RunAtLoad false`, `StartCalendarInterval` arrays for the times above (local time; kickoffs converted from ET using `ds_pro_schedule` `date` values, which are epoch ms [V-03 §A.4], and the machine's zone) **[A-1: launchd fires a missed calendar run once at next wake]**.
- **Keychain under launchd:** a job started by launchd runs as the user but without a GUI session context; whether the keychain read prompts (and where the prompt appears) is **[A-2]** — the same question as plan 02 A-1; `eff doctor` #7 and the first night's `snapshot roster` log answer it. If it prompts, the credentialed jobs use the file store (`EFF_CREDENTIAL_STORE=file` for the jobs only) — the README says so.
- `eff install-launchd` bootstraps with `launchctl bootstrap gui/$UID <plist>`; `eff uninstall` boots them out; `eff doctor` #11 verifies they are loaded and reports last exit codes from `refresh_log`.
- **Overlap and concurrency:** per-job lock row (`job_lock(job, pid, started_at)`); WAL keeps the server reading during loads; the cross-process limiter table (plan 01 §6) means a job and the server together never exceed 30/min.
- **Season awareness:** `news`, `sleeper:trending`, `weather`, `projections`, `pre-kickoff` and the game-day extras consult `ds_pro_schedule`: outside the season (no game in ±7 days) they exit 0 immediately. If `ds_pro_schedule` has never been loaded, `espn:schedule` is the one job that runs unconditionally.
- **Notifications:** `osascript -e 'display notification …'` via `execFile` with an argument array; failures rate-limited per job to one per 6 h; the **drift alarm and the credential-rejected alarm are never rate-limited** (they fire once per state change); informational diffs collapse into one notification per run. Every notification's text is also a `refresh_log.note` so `eff status` shows what was said. No notification ever contains a cookie value, a GUID or a member name (the redactor runs on notification text too).

## 3. Failure-signal summary

| Channel | Red when | Who sees it |
|---|---|---|
| GitHub check | any `ci.yml`/`docs.yml` job fails | Chad; the orchestrator verifies after every push |
| `refresh_log.ok = 0` | a launchd job failed after retries | `eff status`, `eff doctor` #9–#11 |
| `drift_state` red / `host_moved` | the probe found a removed key, a changed enum, a 3xx or non-JSON host answer | notification (always), `eff status`, `doctor` exit 4, `meta.drift` in every affected tool result |
| `credential_state = rejected` | any cookie-bearing 401/403 | notification once, `eff status`, `doctor` exit 3, `ESPN_AUTH_REJECTED` in tool results — and **every job goes quiet** until `eff setup` |
| macOS notification | a job failed (rate-limited), a roster/pool diff, a pre-kickoff problem, drift, credential rejection, a crosswalk gap | Chad, without opening anything |
| `eff status` / `espn_get_status` | any source past its hard limit; probe older than 36 h; snapshots missing; jobs not loaded; requests in the last minute near the cap | Chad, or the model when asked |
| Scrub deny-list abort / manifest test / identifiers job | an identifier survived scrubbing, a fixture was hand-edited, or a real path/GUID/IP/league id landed in a tracked file | the person recording; CI |

## 4. Build order for this inventory

1. **Now (docs-only repo):** `docs.yml` (Mermaid, links, identifiers), the `secrets` job + `.gitleaks.toml`, `dependabot.yml`, `PULL_REQUEST_TEMPLATE.md`, the branch ruleset, **`scripts/probe.ts`** (standalone, `npx tsx`, keyless host probe + optional public-league shape probe against a checked-in key list), the **keyring review** (plan 02 §7.2, a reading task).
2. **With the first `package.json`:** `ci.yml` skeleton (lint/typecheck/audit/no-scripts/license/pack/identifiers), `scheduled.yml`, the scrub script against the anonymised shapes.
3. **With the store and sources:** `eff refresh *` (ESPN keyless views first — they make the game-window logic real), `eff probe` as a subcommand, `install-launchd`, `store prune/backup`, crosswalk rebuild.
4. **With the ESPN provider and a stored cookie:** snapshots (roster, pool, projections), transactions append, credential check, private-view fixture recording, `eff smoke`, pre-kickoff check.
5. **With the gate (writes phase):** journal reconcile.
6. **Before the first release:** Inspector smoke, evals, release workflow, pre-release checklist.
