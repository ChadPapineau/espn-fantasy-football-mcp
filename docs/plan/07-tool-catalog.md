## 2. Conventions shared by every tool (stated once)

- **Common inputs.** `force_refresh?: boolean` (ESPN-fact tools only; once per 60 s per key, plan 01 §5.3); `allow_stale?: boolean` (plan 01 §5.4); `detail?: "compact" | "full"` (C2). `week` is `scoringPeriodId` `1..18` (kickers carry 19–22 only inside ESPN's own splits; tools reject > 18 with a hint); omitted = `clock.current_matchup_period`'s scoring period. `season` is `2018..current` (03 §A.1; older → `VALIDATION`). `team_id` is `1..20`; omitted = `my_team` (from `SWID ∈ owners[]`, plan 03 §2.1 step 6) — a tool that needs `my_team` when none resolved returns `VALIDATION` with the hint "pass `team_id` or run `eff setup`".
- **Toolset (C3).** `EFF_TOOLSET=core` (default) registers the 18 P0 tools; `full` adds the 16 P1 tools. Write tools are gated separately (plan 02 §3.2). Registry order is fixed (plan 01 §3.1); `tests/smoke/expected-tools.json` holds both lists (18 and 34). `EFF_TOOLSET` and `EFF_SEEDING_MODE` are config keys in plan 03 §3 (T-03, resolved in R1).
- **Common outputs.** The plan 01 §4.2 envelope. Analytics tools additionally carry `data.inputs[]` (each contributing dataset with `source, as_of, age_s, freshness`) and `data.rec: Rec`; `meta.estimate: true` on every number that is ours (plan 01 D15); ESPN-native numbers are named `*_espn` and never averaged into ours silently (C13). Missing drivers are named in `rec.assumptions[]` (plan 01 §5.7).
- **Errors.** Plan 01 §4.3 codes only. A write-path validation failure is `VALIDATION` at `prepare` time, never a `commit` failure (06 §A.1). A tool that needs cookies on a private league with none stored returns `ESPN_REQUIRES_COOKIES`; a rejected cookie returns `ESPN_AUTH_REJECTED` or stale cache with a warning (plan 03 §6).
- **Annotations.** By family (plan 01 §4.1): ESPN facts `R+open`; ESPN-native estimates `R+open` with the label; our analytics `R, idempotent:false, open:false`; external text `R+open`; ops `R, open:false`. **`espn_record_recommendation`, `espn_prepare_*` and `espn_cancel_prepared` are local-store writes** (`readOnlyHint: false, destructiveHint: false, idempotentHint: true|false, openWorldHint: false`) — the sixth family in plan 01 §4.1 (sib ADV OBJ-19 conceded the mislabel; T-04, resolved in R1).
- **Provenance.** `meta.source[]` names every contributing view or dataset (`espn:mRoster`, `espn:projection`, `nflverse:stats_player_week`, `store:pool_snapshot`); `meta.attribution` carries the plan 01 §4.2 ESPN line whenever `espn:*` is in `source`, nflverse CC-BY and FTN/ffopportunity CC-BY-SA when they are (04 §E); Sleeper and Open-Meteo carry `license: "non-commercial"`.
- **Degradation.** Every ESPN-fact tool states below what it does when its view is missing or drifted (plan 01 §7 table restated per tool); every analytics tool lists which inputs it can lose and still answer (`partial: true`, `assumptions[]`), and which loss stops it.
- **Budget.** ≤ 3 upstream requests per call (plan 01 §5.6); a 4th need → `partial: true` and a warning naming the missing input. Cold-cache counts are given per tool; warm-cache is 0 for every ESPN-fact tool within its class TTL.
- **Token-cost note format.** `typical / worst` serialised characters at `detail: compact`; worst is the halving point.

### 5.1 Worst-case sizes (serialised chars at `compact`; the halving point is the budget)

Claude Code warns at 10 000 tokens and truncates at 25 000 by default (06 via sib §A.1); 20 000 chars ≈ 5–7k tokens, so no *single copy* of a result approaches either limit. **Whether the clients forward both copies of a result** (`structuredContent` and the `text` block — plan 01 §4.2) is unverified; the sibling conceded a week-one spike (sib ADV OBJ-06) and so does this plan: a fixture-mode-only `espn_debug_echo` returns a nonce only in `structuredContent`, each client is asked to repeat it, and the answer goes into HANDOFF; this table is re-based on measured tokens per client afterwards (plan 10 A-6; T-06 — plan 01 §4.2 carries the rule).

**Per-turn fixed cost — definitions, not results.** A client without deferred tool loading pays `tools/list` every turn: per registered tool its description (the tool's own sentence plus a ≤ 40-char pointer to the server `instructions`, where both mandatory sentences live **once** — sibling round-2 OBJ-28, carried by ADV OBJ-09(b)), its `inputSchema` and its `outputSchema` (C10), plus the Skills listing (13 × ≤ 350 chars, plan 09 §2) and the prompts list. Controls: `EFF_TOOLSET=core` as the default (C3), static descriptions (§5.4), and — if the ceiling is exceeded — C10's escape. Measurement: `tests/mcp/size.test.ts` records `tools/list` bytes **and tokens** under `core` and `full` and the Skills listing chars in fixture mode against ceilings — **`core` ≤ 20 000 chars ≈ 5 k tokens (18 tools), `full` ≤ 35 000 (34), Skills listing ≤ 4 600 chars [A-4]** — and the numbers land in plan 10 §2's ledger. The ceilings are **token-derived and downward-only**: a ceiling set above the design's size is a description, not a budget, so a ceiling may be lowered on measurement and never raised; the rule "definitions are budgeted like results" is not a constant either.

### 5.2 What `detail: "compact"` drops (and why the Skills can rely on it)

`compact` keeps every identifier, every number a decision needs, every `Dist` with its `basis`, every ESPN-labelled comparator, and every `flag`; it drops per-game rows (usage), per-week arrays beyond three weeks (projections `ros`, ESPN `weekly`), raw `stats{statId}` maps (box score, player stats, projections), `stat_line_expectation`, `flex_allocation_trace`, `weekly_impact` beyond four weeks, `evidence` strings inside signals, and the `season_outlook` paragraph. `full` is for the retrospective, the golden diagnostics and debugging. The cheat-sheet (`espn-ff://docs/tool-outputs`) lists the exact field set per tool per level so a Skill never asks for `full` to find a field `compact` already has.
